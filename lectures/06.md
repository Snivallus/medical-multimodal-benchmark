# 认知智能前沿技术与实践

### 摘要

### 知识表示与知识图谱管理

本节进入知识图谱管理部分，核心内容包括知识表示、知识图谱表示学习、存储架构与查询技术。知识表示之所以重要，是因为现实生产中的数据必须先进入计算机，被有效存储、表示和组织，才可能进行后续的分析、推理与计算。传统知识表示多走符号化路线，如谓词逻辑、框架、OWL、语义网等；本节则进一步引入与统计学习密切相关的向量化表示，并讨论二者如何结合。

老师将知识表示的用途概括为五个方面。第一，支持客观事物在机器中的有效表示与标识，把现实世界中的事物和关系转换为可处理、可计算的形式。第二，提供领域中的本体、约定与概念模型，明确概念类别及概念之间的关系，为应用研发提供统一语义规范。第三，作为推理的表示基础，使计算机能够基于已有知识进行逻辑推导。第四，便于设计适合计算机高效计算的数据结构。一个系统不能只在逻辑上“聪明”而计算很慢，实际应用必须兼顾查询、推理与计算效率。第五，知识表示还应尽可能保留人类可理解性，尤其在医疗、生产决策等严肃场景中，结论需要依据与可解释性。可解释性通常面向用户与决策者，使结果能够被信任。

从知识表示框架看，其核心围绕实体标识、概念模型、推理能力、计算性能与人类可读性展开。实体 ID 为每个实体分配唯一标识；概念模型搭建知识框架；表示形式还要兼顾推理、计算与可读性。因此，知识表示本质上是建立一套能够同时支持机器存储、计算、推理，并具有一定人类可解释性的表示框架。知识图谱正具备这种综合特性。

### 知识图谱的多学科基础与表示形态

知识图谱本身是一种符号化表示，其内核是图结构，即点边结构，因此离不开图论。除图论外，还涉及逻辑学与概率论。逻辑学侧重严谨的形式化定义，可描述规则、公理并支持逻辑推理，适合表达确定性知识；概率论与概率图模型则面向不确定性、模糊性和知识不完全的场景。例如“明天是否下雨”并不能百分之百确定，知识常带概率与置信度。概率图模型结合图论与概率论：节点表示随机变量，边表示概率依赖关系。例如天气为阴天会影响是否下雨，下雨又影响草地湿度。知识图谱项目中应根据业务场景与知识确定性程度选择合适的表示方法。

传统符号表示包括基于规则、描述逻辑、框架、产生式规则，以及基于图结构的语义网、树形结构、RDF 图和属性图等。符号表示通常对人类友好、可读性强；向量表示则将对象嵌入低维稠密空间，便于神经网络与统计模型计算，但人类不易直接理解。例如图像嵌入为向量后，人很难从单个向量看出“猫在玩小鱼”的语义，但向量便于模型完成复杂任务。当前一个重要方向是**神经符号结合**：既保留知识图谱的符号结构，又利用向量化表示增强计算与学习能力。智能体记忆系统等场景也可以考虑符号与向量两种形态共存。

### 三元组与知识图谱表示学习

知识图谱通常以三元组表示，常见形式为 SPO，即主体、谓词、客体，也可写为 HRT，即头实体、关系、尾实体。最简单的处理方式是把三元组集合视为文本集合，借用自然语言处理中的表示学习方法，如词向量模型，将每个 term 映射为低维数值向量。但知识图谱本身是图结构数据，具有拓扑关系，因此更合适的一类方法是知识图谱表示学习，即 KGE。它与一般图学习如 GCN 等有联系，但本节主要讨论知识图谱特有的表示学习。

在介绍知识图谱嵌入前，需要理解 one-hot 与词袋模型。**One-hot 表示**给词表中的每个词分配一个 $K$ 维向量，只有该词对应位置为 1，其余为 0。它简单、可直接用于初始化，但非常稀疏，特征表达能力浅。**词袋模型**将文档视为无序词集合，只统计词频，把词频作为文本特征。它简单有效，但忽略词序会带来严重问题：例如“小明跑得比小李快”和“小李跑得比小明快”词集相同，词袋表示无法区分语义。

因此自然语言处理中强调**分布式语义**：词义可由上下文决定。一个词经常与哪些词共同出现，就与其形成语义联系。例如“天安门”常与“北京”“中国”共同出现，其向量就会在语义空间中靠近相关概念。词向量将词映射为低维稠密向量，向量距离反映对象之间的语义关联，是一种特征抽取方法。经典词向量还能刻画类比关系，如“罗马—意大利”和“巴黎—法国”在向量空间中具有相近的首都关系。

知识图谱表示学习的核心可概括为两件事：定义**打分函数**和配套的**损失函数**。对真实三元组 $(h,r,t)$，希望打分函数给出的分数尽可能符合“真实”；对负采样得到的不存在三元组 $(h',r,t')$，希望分数与其拉开差距。训练时通常采用随机梯度下降迭代更新实体与关系向量，使正例得分更优、负例得分更差。负采样十分关键，也存在风险：当前图谱中不存在的边未必在未来不成立，可能只是构建时漏抽或文档未提及。因此不同负采样策略会影响模型性能。

### 经典知识图谱嵌入模型

**TransE** 是最早且直观的平移模型之一。其思想是把关系看作头实体到尾实体的翻译：
$$\mathbf{h}+\mathbf{r}\approx \mathbf{t}$$
对真实三元组，希望 $\|\mathbf{h}+\mathbf{r}-\mathbf{t}\|$ 尽可能小；对负例则希望距离较大。例如已知“复旦大学—位于—上海”，给定头实体与关系，应能推断尾实体。TransE 简单、训练快，但难以处理三类关系。第一是自反关系，如夫妻、朋友等对称关系：若 $e_i$ 与 $e_j$ 具有关系 $r$，反向也具有 $r$，则模型会推出 $\mathbf{e}_i\approx\mathbf{e}_j$ 且 $\mathbf{r}\approx 0$，实体难以区分。第二是多对一关系，如多个人的出生地都是青岛，多个头实体对应同一尾实体，模型难以区分这些头实体。第三是一对多关系，如一部电影对应多位演员，模型难以区分多个尾实体。

**TransH** 在 TransE 基础上引入关系专属超平面。对每个关系 $r$ 设置法向量 $\mathbf{w}_r$，将头实体和尾实体投影到该关系超平面上：
$$\mathbf{h}_r=\mathbf{h}-(\mathbf{w}_r^\top\mathbf{h})\mathbf{w}_r,\quad
\mathbf{t}_r=\mathbf{t}-(\mathbf{w}_r^\top\mathbf{t})\mathbf{w}_r$$
并要求
$$\mathbf{h}_r+\mathbf{r}\approx\mathbf{t}_r$$
这样同一实体在不同关系下可以有不同的表示，从而缓解自反、一对多、多对一问题。不过 TransH 仍在同一实体空间中建模，对同类型实体的区分仍有限。

**TransR** 进一步提出实体空间与关系空间分离。实体位于实体空间，关系位于关系空间；对每个关系学习一个投影矩阵 $\mathbf{M}_r$，将头尾实体投影到关系空间：
$$\mathbf{h}_r=\mathbf{M}_r\mathbf{h},\quad
\mathbf{t}_r=\mathbf{M}_r\mathbf{t},\quad
\mathbf{h}_r+\mathbf{r}\approx\mathbf{t}_r$$
其表达能力更强，能处理同一关系下不同实体类型的差异。例如“马克思—民族—犹太民族”和“恩格斯—民族—支民族”中人物实体与民族实体类型不同，若共享同一关系超平面可能产生干扰。TransR 为每个关系设置独立投影矩阵，但参数量显著增加，训练成本高且容易过拟合。总体比较：TransE 最简单；TransH 用超平面投影，参数量较小；TransR 用关系专属矩阵，表达能力更强但参数多。三者都保留平移思想。

**TransD** 针对 TransR 参数过大的问题，为每个实体和关系分配向量，用向量乘积构造投影，替代大型矩阵，从而减少参数量、缓解过拟合，支持更大规模知识图谱。**RESCAL** 则将整个知识图谱视为三维张量，通过张量分解得到核心张量与因子矩阵。核心张量刻画关系结构，因子矩阵每一行对应实体向量；对候选三元组打分可判断其成立程度，并用于排序或置信度预测。其优点是统一建模实体与关系，利用实体间关联进行集体学习；缺点是关系种类多时参数量急剧膨胀，泛化性可能变差。**DistMult** 将关系矩阵限制为对角阵，减少参数量并缓解过拟合，但仍采用线性变换思想。

**RotatE** 跳出平移框架，受欧拉公式启发，将实体和关系映射到复数空间，把关系看作复平面上的旋转操作：
$$\mathbf{t}\approx \mathbf{h}\circ \mathbf{r},\quad |r_i|=1$$
即头实体经过关系旋转后接近尾实体。它可较好支持对称性、多对一和一对多关系，工程落地容易，时间与空间复杂度为线性。但由于使用复数表示，实体向量维度会分为实部与虚部，这是与实数空间模型的重要区别。

知识图谱表示学习可支撑链接预测、问答系统和推荐系统等任务。链接预测是给定头实体和关系预测尾实体，或判断两实体间是否存在某关系。问答中可将问题实体和关系嵌入，通过向量运算在候选库中寻找最近尾实体；推荐中可嵌入用户行为与商品，学习偏好关系。不过这类方法共同缺陷是可解释性较差，且难以加入显式知识约束，如“产品价格必须低于某值”这类硬约束在纯嵌入学习中不易保证。

### 知识图谱存储架构

知识图谱的核心组织形式是三元组，即主体、谓词、客体三列，因此可直接用关系数据库中的一张大表存储。OpenLink 等系统曾用大表存储完整知识图谱，并可对频繁出现的客体做简单映射压缩，但这难以应对复杂图查询与分析。围绕关系表思想，有三类优化技术。

**属性表方法**在主表外存储若干聚类属性表，将具有相似属性的实体聚在一起并拉平存储。例如书籍类实体常共享出版年份、版权等属性，可放入小表。查询时可直接在小表上做选择操作，避免在原大表上做代价较高的连接操作。其优点是减少全表扫描和连接，但聚类表可能产生空值，因为并非每个实体都具备该属性。**垂直划分方法**为每个关系建立只含两列的小表，分别存头实体与尾实体，从而天然避免空值，并减少连接。但其索引通常以谓词为索引，若查询以尾实体为值进行反向查找，效率较低。**全索引方法**如德国马普所相关系统，进一步对 SPO 的多种排列建立索引，既以谓词为索引，也以主体、客体等为索引，存储六种排列。其优点是无论查询 S、P 还是 O 都较高效；缺点是存储代价大，更新维护成本高，尤其面对流式数据时几乎不适用。

与之相对，**图原生数据库**如 Neo4j 不再用关系表模拟图，而是直接以点边结构存储知识图谱，对复杂图查询更有利。分布式存储则把数据分布到多台机器上，但逻辑上仍是一个整体。数据划分有两类：一类基于云平台内嵌的分片接口，如 Hadoop 生态；另一类需要自行设计划分方法。自行设计方法中，**基于粗化**的思想是先把局部子图合并为超点，逐层缩小图规模，足够小后再切片分配，查询时再映射回原图。**基于局部模式**的方法先定义重要查询模式，将大图按模式拆分，再对原始大图做模式匹配，把匹配实例按模式分组并分配到不同机器。其关键步骤是模式匹配与子图同构，而子图同构本身是 NP 难问题，代价较高。还有一种**三元组群**方法，以实体为中心形成星状结构，包括只有出边、只有入边以及混合边的星形局部模式，相对简单。

### 知识图谱查询与 SPARQL

知识图谱查询与一般图查询的显著区别在于语义。一般图可能只有标签，而知识图谱中的实体属性、谓词关系具有明确语义，因此查询设计要充分关注语义特性。本节介绍查询语言、模式匹配、关键字查询等。

RDF 是语义网的标准资源描述框架，SPARQL 是面向 RDF 数据的标准查询语言。它与 SQL 类似，是描述性、结构化查询语言：用户只需描述任务目标，不必规定底层逐步执行过程。SPARQL 常用 `SELECT` 与 `WHERE`。`SELECT` 定义返回变量，`WHERE` 给出基本图模式。例如查询某本书的标题：
```sparql
SELECT ?title
WHERE {
  <book1> <title> ?title .
}
```
其中 `<book1>` 是 URI，`?title` 是变量。SPARQL 支持 `PREFIX` 简写 URI。`FILTER` 可加过滤条件，如正则表达式要求标题以某字符串开头：
```sparql
FILTER regex(?title, "^...")
```
也可做数值约束，如价格小于 30.5。`OPTIONAL` 表示可选匹配：由于数据可能不完备，某些人可能没有邮箱，若严格匹配该边则结果为空；加上 `OPTIONAL` 后可放宽约束。`UNION` 则将两个模式的匹配结果合并。SPARQL 与 SQL 相似，但关系数据库执行多步查询时往往需要多次自连接，代价很高；而 SPARQL 查询本身对应一个图模式，可直接在原生图存储上做子图匹配，因此图原生存储更适合复杂图查询。

### 子图匹配与子图 Skyline

SPARQL 查询本质上是在大知识图谱中匹配一个小查询图，即**子图同构**问题。图同构要求存在节点映射，使对应节点标签相同、边及边标签也相同。子图同构要求查询图 $Q$ 与大图中的某个子图同构。该问题是经典 NP 完全问题，已有 Ullmann、VF2、VF3 等算法，实际系统在数千万条边规模上也可实现较快查询。

模式匹配可能返回大量同构结果，因此引入**子图 Skyline**。先理解普通 Skyline：选择酒店时希望价格低、距离近，若酒店 A 在价格和距离上都不劣于 B，且至少一个维度更优，则 A dominate B，B 不会被选择。Skyline 返回不被任何其他对象 dominate 的集合。子图 Skyline 将此思想用于图匹配结果：两个图首先同构，其次对应数值节点满足“越小越好”的偏序关系，若图 $G_1$ 在每个对应数值上不劣于 $G_2$，且至少一个更小，则 $G_1$ dominate $G_2$。由此可从海量匹配结果中筛选更优子图。

### 近似查询与语义编辑距离

精确子图匹配要求结构完全一致，复杂度高，且用户难以预知底层数据的全部模式。近似查询允许一定松弛。基于本体的近似查询利用本体中的上下位关系计算概念相似度。本体可理解为描述概念层级关系的 DAG 或树。仅用本体距离判断相似度有局限，例如“电动汽车—汽车”与“电动汽车—太阳能汽车”距离可能相同，但语义接近程度不同。常用最近公共祖先的深度衡量相似性：公共祖先越深，概念越具体，二者越相似。近似匹配可要求对应节点标签相似度不低于阈值 $\theta$，但边结构仍保持，因而精确匹配是近似匹配的特殊情况。其优点是考虑节点语义、支持 top-$k$ 检索；缺点是仍需指定阈值与 $k$，复杂度高，且未充分考虑结构相似性。

更进一步是**语义图编辑距离**。传统图编辑距离允许顶点、边的增删与替换，编辑代价为 0 或 1，但缺乏语义。语义编辑距离为编辑操作赋予语义代价。例如删除或增加顶点时，可根据概念在本体中的祖先集合计算距离；若概念相同，距离为 0。除六种基本编辑操作外，还引入三类语义 shortcut，且代价为 0：**边重定向**，如“国家—语言”与“语言—located in—国家”语义等价；**路径替换**，如“人—出生地—国家”可等价替换为“人—出生地—城市—国家”；**星形替换**，如“大众—类型—汽车、大众—装配—澳大利亚”可等价于“大众—类型—澳大利亚汽车”。这些等价关系必须提前挖掘，不能任意替换。基于语义编辑距离的近似搜索复杂度更高，图编辑距离是其特例。系统通常采用两阶段方法：离线构建**语义摘要图**，将原始知识图谱逐层压缩抽象，越往上越像 schema；在线查询时进行查询重写，利用三种 shortcut 生成等价查询，再自顶向下在摘要图上剪枝匹配，逐层缩小候选空间。

### 关键字查询与最小斯坦纳树

关键字查询是知识图谱查询中的经典问题。给定若干查询关键词，先在知识库中命中候选实体，再寻找一个子图以最小代价将这些候选点连通，这对应**最小斯坦纳树**问题。候选实体称为终端节点，为连通它们而引入的额外节点称为斯坦纳节点。若边有权重，则最小化权重和；若无权重，则最小化边数。

最小斯坦纳树是 NP 难问题，但有两个重要特例：当关键词数量 $K=2$ 时，退化为最短路径问题；当 $K$ 等于全部图顶点时，退化为最小生成树问题，二者均有多项式算法。一般 $K$ 下可用精确或近似算法。精确方法之一是暴力枚举额外节点集合，再求最小生成树，代价极大。改进方法先构建所有节点两两最短路径组成的完全图，再在完全图上枚举额外斯坦纳节点；由于完全二叉树引入中间节点最多，$K$ 个叶节点最多引入 $K-1$ 个非叶节点，而两端点可直接相连，因此最多枚举 $K-2$ 个额外节点。其瓶颈是构建完全图的存储与计算代价。近似方法一仍构建完全图，然后对 $K$ 个终端节点求最小生成树，可得到近似比为 2 的解。近似方法二更实用，不需构建完全图：先选一个终端节点构成当前树，迭代选择尚未覆盖的终端节点到当前树距离最近的路径加入，直到覆盖全部终端节点。该方法本质是贪心，可处理更大规模图。

总体而言，知识图谱查询任务虽然多样，但应抓住两条主线：效果层面要关注语义与图结构，效率层面要设计合适索引与算法。
