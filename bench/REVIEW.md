## 一、结论

1. **结构完全合规**：选项数、ID、正确答案、主诊断、合并症、图片齐全性等 11 项硬性检查全部 0 错误。
2. **内容有 4 类实质缺陷**，集中在 6–8 道题，其中 `iiyi-0088` 是数据缺陷而非题目难度问题。
3. **图文本轮没有带来任何增益**：4 道同时跑了「图文」和「纯文本」的题，分数**完全相同**，`Δacc = 0`；另有 1 道只有图文条件，模型反而多选了一个错项。
4. **根因找到了**：数据集里的图片大多是 **150 px 缩略图**（181 张中 137 张长边 ≤ 200 px，100 道题里 72 道的图**全部**是缩略图）。页面上的原图是 500–900 px，旧爬虫存的是 `_w150` 版本。在这种分辨率下，任何视觉模型都读不出影像学征象。
5. **文本盲测已经到 0.767**（疑点题 0.833 / 对照题 0.633），意味着 `Δacc` 的理论上限只有约 0.23，而实测为 0。

**判断：先把图片换掉，再谈 `Δacc`；否则这套题测的是"模型能不能从文本猜到诊断"，而不是"图像是否必要"。**

## 四、逐题发现（附模型原话）

### `iiyi-0088`：解析缺陷，必须修

原文 `诊断结果`：`病例1：乳腺成肌纤维细胞瘤；纤维腺瘤。病例2：乳腺成肌纤维细胞瘤。`
解析按"；"切分，于是正确项变成：

- `病例1：乳腺成肌纤维细胞瘤`
- `纤维腺瘤。病例2：乳腺成肌纤维细胞瘤` ← 两条诊断被拼成一条，且把病例 2 的诊断粘在病例 1 后面

模型原话："病例1为乳腺成肌纤维细胞瘤并伴纤维腺瘤，病例2亦为乳腺成肌纤维细胞瘤，故选D、E" —— 它靠猜读懂了坏掉的选项。同时该题把**两名患者**塞进一题，却只配 1 张图。

### `iiyi-0103`：正确答案集不完整，模型答对却被扣分

`诊断结果` 只有"狼疮肾炎（II型+V型）"，但患者有明确的狼疮皮肤表现（下肢融合性皮疹、冻疮史），`皮肤型红斑狼疮` 作为选项在临床上站得住。模型选 C+D，被记为 `FP`，得分 0。模型原话："……幼年冻疮史及下肢融合性皮疹伴色素沉着符合皮肤型红斑狼疮"。

同一题的图是 **150×166 px**，模型不可能读出病理分型，只能靠文本猜"II+V 型"——它能选中 C 属于运气。

### `iiyi-0025`：第 3 个正确答案不可达

正确项含"右下肢肌间静脉血栓形成"，但题干（已删影像结论）只描述呕血、便血、血红蛋白下降；两张图是腹部 CT/盆腔 MSCT 缩略图。文本条件（0.67）与图文条件（0.67）都只能拿到 C、E。模型原话只提"大量呕血及休克表现符合胃左动脉破裂出血，干硬便后便血符合直肠前壁撕裂"。

### `iiyi-0043`：伴随诊断被当作必选项

正确项含"慢性非萎缩性-萎缩性胃炎"，属伴随发现（无上腹症状、需胃镜证实），题干只有柏油便与贫血。模型只选 B（0.50）。构造期审计已标明该诊断"无胃镜或病理依据"，却仍然作为正确答案。

### `iiyi-0121`：侧别干扰项诱导幻觉

干扰项 `B. 右股骨近端骨纤维结构不良` 与正确项 `F. 左侧股骨近端纤维结构不良` 只差一个"右/左"。纯文本条件下模型看不到图，却照样选了 B，理由是"影像符合多骨型骨纤维结构不良累及左股骨近端、**右股骨近端**及左胫骨近端"——凭空补出了右股骨。

### `iiyi-0073`（对照）：正确答案实际上不可达

题干只有腹部不适、腹泻、CA125 升高；`诊断结果` 是"肝左叶上皮样血管肉瘤伴腹腔广泛转移"，需穿刺病理与免疫组化。模型选了 `卵巢癌根治术后、肝转移`（CA125 的直接联想）。该题的两张图也是缩略图。

### `iiyi-0065b`：靠"培养阴性"猜中结核

正确项含"腰椎内固定术后伤口结核菌感染"，题干只写切口流脓、ESR 38、普通培养阴性。模型据此推出结核（"普通细菌培养阴性支持……结核菌感染"）——结论对了，推理是概率性的，换成任何"培养阴性的慢性感染"都成立。

### 真正的第二个问题：图片不是"诊断性影像"

另做了一次纯看图描述（不给题干、不给诊断）：

- `case_0314`（`0103`）的图是一张**病理报告截图**：左边是 4 张染色照片，下方是一整段中文图注——"A:HE染色可见系膜细胞数目增多…E:免疫荧光IgG4阳性…F:免疫荧光PLA2R阳性…图1 肾脏病理结果"。模型原话逐字复述了这些条目。也就是说，**被从题干里删掉的病理结论，原封不动地印在图片上**。
- `case_0000`（`0000`）的图是一张**关节镜术中照片**，画面上烧着红字"髁间窝扩大成型后进行韧带重建"。这是术后重建完成的状态，既不是诊断性影像，又直接把"韧带重建"写在了图上。
- `case_0107`（`0049`）的图是口内照片（牙列像），而病例的结论来自曲面体层片与锥形束 CT——图和结论不是同一个检查。
- `case_0194`（`0065b`）的腰椎 MRI 是真影像，但模型描述的是"椎管内背侧团块状异常信号"，与病例结论"腰背部软组织感染"并不对应。

结论：**图文条件目前测的是"能不能读图上的中文结论"，不是"能不能从影像看出诊断"。** 换原图不会改变这一点——全量重下后再测 5 题，得分仍然一分不差。

### 因此 P0 需要补一条

4. **图片审查**：逐张确认"这张图本身是否足以支持该诊断"，并把两类图剔除或单列——
   - 报告截图/带完整图注的拼图（结论写在图上）；
   - 术中照、术后照、标本照（不是诊断当时的影像）。
   100 道题共 181 张图，人工过一遍约 1–2 小时；也可以先用视觉模型自动打标签（诊断性影像 / 报告截图 / 术中术后照 / 带烧录文字 / 无法判读）粗筛，再人工确认被标记的那些。

如果这一步不做，`Δacc` 只能反映 OCR 能力，proposal 里"图像是否必要"的问题就答不了。

## 八、全量图片分诊（2026-10-23）

上面第二节第 4 条要求"逐张确认这张图是否足以支持该诊断"。这一步做完了：`bench/triage_images.py` 对 **181 张图逐张**调用 `Qwen3.8-Max`，只问三个问题——这是什么图、看到了什么、图上写了什么（逐字转录）——**不给题号、不给选项、不给答案**；拿到转录后由脚本在本地和 `main_diagnosis` / `diagnoses` 做字符比对，判断"答案是不是印在图上"。181 次调用约 40 分钟，1 张超时，`--retry-errors` 重跑通过，0 缺失。产出 `bench/IMAGE_TRIAGE.md`（清单，本次清理中已删除），逐图原始记录只留在本地（`bench/results/` 本就不入库），也已删除。

### 图片构成

| modality | 张数 | 说明 |
| --- | --- | --- |
| 影像 | 124 | X线 / CT / MRI / 超声 / 造影 |
| 病理切片 | 25 | HE、免疫组化 |
| 临床照片 | 17 | 体表、术中、标本 |
| 内镜 | 7 | 关节镜、喉镜、胃肠镜 |
| 检验报告 | 4 | 化验单、超声报告等打印件 |
| 病历文本截图 | 2 | 以文字为主的界面截图 |
| 示意/其他 | 2 | 多模态拼图 |

### 关键发现：一半的题目把答案印在图上

- **83 张**图的转录里出现"图 1 / 图 2 / 1a"这类**期刊图注**；**71 张**图上的文字本身就是检查结论。
- **50 道题**（`items.jsonl` 的一半）至少有一张这样的图。
- 原文举例（`case_0295`，`iiyi-0096`）：图注逐字为"**图1 患者，男，44岁，C6椎板软骨瘤** 1a. 术前颈椎横断面CT扫描示C6左侧椎板骨性赘生物突入椎管压迫硬膜囊…"。我人工打开这张图核对过，图注确实烧录在图的下半部分。

这解释了为什么换原图之后 `Δacc` 一分不差：`text_b` 把影像结论从题干里删掉了，图片却把同一句话原封不动地还回来。**当前 `photo` 变体测的是"能不能读图上的中文图注"，不是"能不能从影像读片"。**

### 三档分级（最差的一张图决定整题）

- **A**：影像 / 病理 / 内镜，图上只有"术前脑CT"这类标注或没有文字 —— 可以当作视觉证据。
- **B**：临床照片（术中、体表、标本）、拼图或无法判读 —— 弱证据，人工看。
- **C**：检验报告、病历截图、转录文字写出了结论、或正确答案字符直接出现在图上 —— 图文条件等于 OCR。

结果：**题 45 A / 4 B / 51 C；图 98 A / 10 B / 73 C。**

只有 5 道题是"答案字符串逐字出现在图上"，但 C 档有 51 道——因为图注的措辞和选项措辞通常不同（"C6椎板软骨瘤" vs 选项"颈椎椎板骨软骨瘤"），按字符比对会漏，按"文字是否陈述结论"才抓得住。所以分级用的是后者。

### 对结论的影响

- **A 档 45 题**：图里没有答案，是唯一能用来回答"图像是否必要"的子集。
- **C 档 51 题**：要么裁掉图注、要么换图、要么从图文条件里剔除，否则 `Δacc` 这个指标无法解释。
- **A 档也不等于"图能支持诊断"**：它只保证图上没写字、且是影像类。病灶是否可见仍需人工确认，但范围从 181 张缩到 98 张。

### 修复尝试：自动裁图注（已回退，2026-10-27）

按上面的建议做了"裁图注 + 复验"，脚本是 `bench/strip_captions.py`。

1. **定位**：先问视觉模型"这段成段的说明文字在上边还是下边、占图高多少"。没有用像素启发式——试过按"底部连续亮区"判断，图注文字本身只有 30–40% 的亮像素，和亮背景的影像分不开，全量跑下来一条都没找到。
2. **裁剪**：按模型给的比例从对应边裁掉，再用与分诊相同的提示词重新描述裁剪后的图。
3. **复验**：四个条件全部满足才接受——图上**不再陈述结论**、**不含正确答案字符**、**仍能看出东西**（`findings` 不为空、不是"无法判读"）、**残留文字不超过 40 字**。第一档不过就往下多裁 8%，最多裁到 60%（再深就不是"裁图注"而是"删影像"了）。

结果：

| | 张数 | 说明 |
| --- | --- | --- |
| 裁掉并复验通过 | 61 | 图注消失，影像面板保留 |
| 裁不掉 | 5 | 文字直接烧在片子上（阅片器叠加、关节镜照片上的红字），或整张就是报告截图 |
| 未完成 | 7 | API 配额在跑到最后 12 张时耗尽（`token quota is not enough`），这 7 张仍是原图 |

题目分级曾从 **45 A / 4 B / 51 C** 变成 **74 A / 14 B / 12 C**。

**这一轮裁剪已整体回退**（commit `203a152` 之前的 `21519fe` 状态）：裁多裁少由模型的比例决定，边界不精确——`case_0295` 把下半部分的病理小图一起裁掉了，`case_0336` 这类窄图也容易切到影像。改为**人工裁剪**；本报告写作时 `bench/data/images` 仍是未裁剪的原始图版，`IMAGE_TRIAGE.md` 也按原图重算（回到 45 A / 4 B / 51 C），此后的裁剪见文首 10-27 注。

留作参考的两点：

- `strip_captions.py --dry-run` 不做任何修改，只让模型指出每张图的图注在哪条边、约占多高，人工裁剪前可以先跑一遍拿到候选比例（例如 `case_0295` 给的是"下边 50%"）。
- 有 6 道题的图**裁不掉**：`0000`（关节镜照片上烧着"髁间窝扩大成型后进行韧带重建"，MRI 上叠着"前交叉韧带断裂"）、`0013`、`0019`、`0044`、`0050`（图就是化验单/病历文本截图）、`0111`。这几道要么换图，要么从图文条件里去掉。

评测口径（最终只报一套图，条件为 `photo` / `text_b`，另加 `text_a` 作难度上界）、要填哪些表、三种结论分别怎么写，见 **[`RESULTS.md`](RESULTS.md)**。

## 九、局限

- 盲测是**单模型、单样本、temperature 0**，15 题的均值标准误约 ±0.1，只能作方向性判断。
- 换原图后重跑的只有 5 题；"图像对这批题没有增益"仍需更大样本确认。
- 图片分诊是**模型判定**，不是人眼逐张确认：181 张里我人工核对过 3 张（`case_0295`、`case_0134`、`case_0005`），都对得上；A 档 98 张"图上没有字"仍可能有漏。
- 自动裁图注**已回退**，边界由模型给的比例决定、不够精确；`bench/data/images` 当时是未裁剪的原图版，图注后来由人工裁剪（见文首 10-27 注）。
- 分诊只判"图上有没有字"和"是不是影像类"，**没有判"病灶是否可见、是否支持该诊断"**——`case_0194` 那种"图是真实影像但和结论不对应"的情况，A/B/C 分级抓不到。
- **API 配额已用尽**（25M tokens），任何新的分诊/裁剪/评测调用都需要换 key 或等配额恢复。
- 对照组的 5 题是按固定种子随机抽取，若要看整体难度需要全量跑一次文本条件（100 次调用，约 20 分钟）。
